### 0.2 Por que este trabalho existe

O dono do blog avaliou os artigos gerados automaticamente e apontou 7 problemas de qualidade + 2 pedidos de funcionalidade no painel admin. Os artigos melhoraram muito, mas ainda:

1. os nomes dos produtos são títulos crus de marketplace (ex.: `"2026 Teclado Gamer Mecânico 1pcsk1 Com Ñ, Layout de 104"`) — sem marca, sem modelo, ilegíveis;
2. o artigo tem **dois** índices (`Neste artigo` + `## Índice`);
3. o índice não tem hierarquia tópico → subtópico com expandir/recolher, e falta o item "Introdução";
4. os nomes dos produtos são longos demais;
5. produtos de categoria errada entram na lista (headset e mouse em artigo de teclado);
6. não existe critério objetivo nenhum para dizer que algo é "o melhor";
7. imagens de produto faltando / minúsculas / de baixa qualidade;
8. o admin não permite trocar o plano de fundo do blog;
9. não existe tema claro.

**Regra de ouro deste trabalho:** corrigir a **causa raiz**, de forma **genérica**. Nenhuma correção pode ser específica de um artigo. Tudo que for implementado tem que valer automaticamente para todo artigo futuro.

## TAREFA 1 — Limpeza e normalização do nome dos produtos

**Problema (itens 1 e 4 do usuário).** O título do produto é usado cru. Ele vem de:
- `scripts/google_shopping.mjs:72` → `const title = String(it.title || "").trim();`
- `scripts/monitor_api.mjs:58` → idem.

E é consumido diretamente em:
- `buildItemSection` (`scripts/gerar-artigo.mjs:2703`) → vira o heading `## ${p.title}${tagline}`
- `buildComparativoTable` (`:2696`) → vira a célula da tabela
- `buildProductImageTag` (`:880`) → vira o `alt`
- `slugify(p.title)` em `ensureProductImages` (`:984`) → vira o nome do arquivo de imagem

Não existe nenhuma etapa de limpeza entre a fonte e o consumo. **Essa etapa é o que você vai criar.**

**Formato-alvo:** `[Categoria] [Marca] [Modelo] [1–3 características principais]`, no máximo **8 palavras / 60 caracteres**.

| Antes (real) | Depois (alvo) |
|---|---|
| `2026 Teclado Gamer Mecânico 1pcsk1 Com Ñ, Layout de 104` | `Teclado Mecânico 104 Teclas` |
| `Monitor Gamer AOC AGON QUAD 27" QHD 180Hz 0,5ms IPS HDR10 Base Ajustável Q27G4F` | `Monitor AOC AGON Q27G4F 27" QHD 180Hz` |
| `Monitor Gamer LG UltraGear Curvo 34G600A-B 34 QuadHD 2K` | `Monitor LG UltraGear 34G600A-B 34" 2K` |

### 1.1 Criar `scripts/product_naming.mjs` (arquivo NOVO)

Módulo ESM puro, sem dependências externas, sem chamada de rede. Exporte:

```js
export const PRODUCT_CATEGORIES = { /* ver TAREFA 5 — tabela compartilhada */ };
export function detectCategory(title) { ... }   // -> "teclado" | "mouse" | ... | null
export function detectBrand(title) { ... }      // -> "Redragon" | "Logitech" | ... | ""
export function detectModel(title) { ... }      // -> "K552" | "Q27G4F" | ...  | ""
export function extractSpecs(title) { ... }     // -> ["27\"", "180Hz", "RGB"]
export function cleanProductTitle(rawTitle, opts = {}) { ... } // -> string final
```

**Regras de implementação de `cleanProductTitle(rawTitle, { category } = {})`:**

1. Normalize espaços, remova `\n`, colapse espaços duplos, remova aspas duplas soltas.
2. **Remova ruído de vendedor** com uma lista de regex (constante exportada `NOISE_PATTERNS`), aplicada case-insensitive e sem acento:
   `frete gr[áa]tis`, `envio r[áa]pido`, `promo[çc][ãa]o`, `oferta`, `original`, `lacrado`, `novo na caixa`, `pronta entrega`, `garantia \d+ (meses|anos)`, `nota fiscal`, `nf-?e`, `\+ brinde`, `brinde`, `kit \d+`, `combo`, `\d+ ?(un|pcs|pçs|peças)\b`, `com [ñn]\b`, `\bimportado\b`, `\bbarato\b`, `\bnacional\b`, `super`, `top de linha`, `melhor pre[çc]o`, `\bp/\b`, `para pc notebook`, `12x sem juros`.
3. **Remova ano solto no início ou no fim** (`^\d{4}\b` e `\b\d{4}$`) quando o número estiver entre 2015 e 2035 — é o que causa o `"2026 Teclado..."`.
4. **Remova códigos-lixo de vendedor**: tokens alfanuméricos minúsculos misturados sem sentido, ex.: `1pcsk1`. Heurística: token que tem letra **e** dígito, tem ≤ 8 caracteres, está todo em minúsculo no original e **não** aparece na lista de modelos conhecidos → descarte. (Modelo de verdade quase sempre vem em MAIÚSCULA ou com hífen: `K552`, `Q27G4F`, `34G600A-B`, `G Pro X`.)
5. **Corte tudo após um separador de cauda**: primeiro `-`, `–`, `|`, `,`, `/` seguido de mais de 4 palavras, e todo conteúdo entre parênteses/colchetes.
6. **Remonte** o título na ordem canônica:
   `Categoria (capitalizada) + Marca + Modelo + até 3 specs`
   - Categoria: `detectCategory()`, escrita como no dicionário (`Teclado`, `Mouse`, `Monitor`, `Headset`, `Cadeira`, `Mousepad`, `Placa de Vídeo`, `Console`, `Controle`, `Notebook`, `Webcam`, `Microfone`).
   - Não repita a palavra "Gamer" se a categoria já implicar isso — remova `Gamer` do meio; ele só polui.
   - Marca: `detectBrand()` contra a lista `KNOWN_BRANDS` (abaixo).
   - Modelo: `detectModel()` — primeiro token que casa `/\b[A-Z]{1,4}[- ]?\d{2,5}[A-Z-]{0,4}\b/` **ou** que aparece logo depois da marca.
   - Specs: `extractSpecs()` — capture no máximo 3, na ordem de prioridade: tamanho (`/\b\d{2}"|\b\d{2}\s?pol/`), resolução (`4K|2K|QHD|FHD|UltraWide|1440p|1080p`), taxa (`\b\d{2,3}\s?Hz\b`), switch (`Switch (Blue|Red|Brown|Outemu|Gateron)`), DPI (`\b\d{3,5}\s?DPI\b`), conectividade (`Wireless|Bluetooth|Sem Fio|TKL|RGB`), capacidade (`\b\d+\s?(GB|TB)\b`).
7. **Capitalize** em Title Case brasileiro (preposições `de/da/do/e/com/para` minúsculas), preservando siglas em maiúscula (`RGB`, `QHD`, `TKL`, `IPS`, `HDR10`, `DPI`, `Hz`, `GB`, `TB`) e o modelo exatamente como detectado.
8. **Trunque** em 60 caracteres sem cortar palavra ao meio.
9. **Fallback duro:** se o resultado ficar com menos de 3 caracteres ou perder a categoria, **retorne o título original apenas colapsado/aparado** — nunca retorne string vazia.

`KNOWN_BRANDS` (constante exportada, minúsculo → forma de exibição). Inclua no mínimo:
`redragon, logitech, logitech g, razer, corsair, hyperx, steelseries, aoc, agon, lg, samsung, dell, alienware, asus, rog, acer, predator, gigabyte, aorus, msi, benq, zowie, philips, xiaomi, redmi, husky, fortrek, multilaser, warrior, motospeed, akko, keychron, glorious, pichau, rise mode, dt3, kabum, intel, amd, nvidia, sony, microsoft, nintendo, xbox, playstation, thermaltake, cooler master, dazz, mancer, vinik, tgt, sades, jbl, edifier, havit, machenike, evga, zotac, pcyes, duex, elgato, blue, hator, trust, marvo, t-dagger, bloody, a4tech, forcegamer`.

1. **Renomeie** a função para `injectHeadingAnchors(body)` e mantenha toda a lógica de geração de âncoras únicas (linhas 1034–1080).

## TAREFA 4 — Imagens dos produtos: presença, tamanho e qualidade

**Problema (item 7).** Causa raiz, investigada:

1. A imagem vem do campo `thumbnail`, que é o `imageUrl` do Google Shopping (`scripts/google_shopping.mjs:84`). O Serper devolve **thumbnails pequenos** (frequentemente 100–200 px de largura) — daí "imagens muito pequenas / baixa qualidade".
2. `ensureProductImages` (`scripts/gerar-artigo.mjs:979`) aceita qualquer download com `b.length > 2048` (linha 1004) — ou seja, **2 KB é o único critério**. Um thumbnail de 120×120 passa fácil.
3. Não há upgrade de URL. Imagens do Mercado Livre têm variantes de resolução no próprio nome (`D_NQ_NP_2X_...` → substituir o sufixo `-O`/`-I`/`-V` por `-F` e/ou usar `_2X_`), e imagens do Google (`encrypted-tbn0.gstatic.com`) são sempre miniaturas irreversíveis.
4. Quando tudo falha, o item simplesmente sai **sem foto** (linha 1025) — daí "sem imagem".

**Correções:**

### 4.1 Upgrade de URL antes de baixar

Crie em `scripts/gerar-artigo.mjs` (ou melhor, num novo `scripts/product_images.mjs`) a função:

```js
export function upgradeImageUrl(url) {
  if (!url) return "";
  let u = url;
  // Mercado Livre: forcar variante grande
  u = u.replace(/D_NQ_NP_(?!2X_)/, "D_NQ_NP_2X_");
  u = u.replace(/-[OIVSMN](\.(jpg|jpeg|png|webp))(\?.*)?$/i, "-F$1");
  // Shopee: remover sufixo de redimensionamento
  u = u.replace(/_tn(\.\w+)?$/i, "");
  // Serper/Google: parametros de largura
  u = u.replace(/([?&])(w|width)=\d+/gi, "$1$2=1200");
  return u;
}
```

### 4.2 Validar dimensão real, não só bytes

Crie `export function imageDimensions(buf)` que lê o header binário e devolve `{ width, height }` para PNG, JPEG e WebP (sem dependência externa):

- **PNG:** largura = `buf.readUInt32BE(16)`, altura = `buf.readUInt32BE(20)`.
- **JPEG:** varra os marcadores a partir do byte 2; ao encontrar um SOF (`0xC0`–`0xC3`, `0xC5`–`0xC7`, `0xC9`–`0xCB`, `0xCD`–`0xCF`), altura = `readUInt16BE(off+5)`, largura = `readUInt16BE(off+7)`.
- **WebP (VP8X/VP8L/VP8):** leia conforme o chunk; se não souber decodificar, devolva `null` (e trate `null` como "aceitar", para não descartar imagem boa por limitação do parser).

Defina a constante `const MIN_IMAGE_SIZE = 500;` (px). Substitua o critério `b.length > 2048` por:

```js
const dim = imageDimensions(b);
const ok = b && b.length > 8192 && (!dim || (dim.width >= MIN_IMAGE_SIZE && dim.height >= MIN_IMAGE_SIZE));
```

Faça isso via variável `--hex-overlay-color` / `--hex-overlay-opacity` — mas atenção: a cor está dentro de uma data-URI, então a forma limpa é definir **duas** regras (`:root html::before` e `:root[data-theme="light"] html::before`) com a data-URI apropriada.

### 8.4 Alternância de tema

**No `src/layouts/Layout.astro`:**

1. Troque `<html lang="pt-BR" class="dark">` por `<html lang="pt-BR" class="dark" data-theme="dark">`.
2. Adicione no `<head>`, **antes de qualquer CSS**, um script inline síncrono (para evitar *flash of wrong theme*):

```html
<script is:inline>
  (function () {
    var DEFAULT = "__DEFAULT_THEME__"; /* substituido no build pelo valor da config */
    var saved = null;
    try { saved = localStorage.getItem("blog-theme"); } catch (e) {}
    var theme = saved || DEFAULT || "dark";
    document.documentElement.setAttribute("data-theme", theme);
    document.documentElement.classList.toggle("dark", theme === "dark");
    document.documentElement.classList.toggle("light", theme === "light");
  })();
</script>
```

O `__DEFAULT_THEME__` deve vir da configuração do blog (TAREFA 9) — leia o valor no frontmatter do componente Astro e interpole-o.

3. Atualize a `<meta name="theme-color">` dinamicamente no mesmo script (`#050505` no escuro, `#F5F5F7` no claro).

**Botão para o visitante:** crie `src/components/ThemeToggle.astro` — um botão com ícone sol/lua (use o componente `Icon.astro` já existente) e insira-o em `src/components/Header.astro`, ao lado dos demais controles. Ao clicar: alterna `data-theme`, alterna as classes `dark`/`light` no `<html>`, grava em `localStorage` sob a chave `blog-theme` e atualiza a `meta[name=theme-color]`. Respeite `prefers-reduced-motion` e adicione `aria-label` e `aria-pressed`.

### 8.5 Alinhar o Tailwind

Em `tailwind.config.mjs`, os tokens (`surface: #0d0d17`, `primary: #A855F7`, …) são uma **segunda fonte de verdade desalinhada** do `global.css`. Troque os valores hardcoded por referências às CSS vars, ex.: `primary: "var(--accent)"`, `surface: "var(--bg-primary)"`, `"on-surface": "var(--text-primary)"`, `outline: "var(--border)"`. Assim as classes utilitárias do Tailwind passam a seguir o tema automaticamente. Mantenha `darkMode: "class"`.

### 8.6 Verificação de contraste

Antes de encerrar a tarefa, verifique manualmente (ferramenta de contraste do DevTools ou cálculo) que no tema claro:
- texto principal sobre `--bg-card` ≥ **7:1**;
- texto secundário sobre `--bg-card` ≥ **4.5:1**;
- `--accent` sobre `--bg-card` ≥ **4.5:1**;
- texto branco sobre botão `--accent` ≥ **4.5:1**.
Ajuste os hexadecimais se algum não passar.
